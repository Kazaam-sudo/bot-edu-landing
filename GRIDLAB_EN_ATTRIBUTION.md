# GridLab English landing and Telegram attribution contract

Status: prepared on feature branch; not live. This describes the payload generated by `/en.html`. End-to-end attribution is not verified until the bot's actual /start handler is inspected and tested.

## Landing URL for the first English YouTube video

```
https://gridlab.academy/en.html?video_id=GL-V01&lang=en&utm_source=youtube&utm_medium=organic&utm_campaign=GL-V01
```

The page always sets the language field to `en`. The other query parameters are optional; direct visits fall back to source `direct`, medium `organic`, and campaign `evergreen`. CTA placement supplies the content field. The page does not send analytics events to a third-party endpoint.

## Telegram start payload

Format, exactly eight underscore-delimited fields:

```
gl1_{video_id}_{lang}_{source}_{medium}_{campaign}_{content}_{click_id}
```

Example:

```
gl1_GL-V01_en_youtube_organic_GL-V01_hero-primary_a1b2c3d4
```

| Field | Meaning | Maximum |
|---|---|---:|
| `gl1` | Schema version | 3 |
| `video_id` | Video / content identifier; `direct` if absent | 11 |
| `lang` | Landing language | 2 |
| `source` | UTM source or YouTube referrer fallback | 7 |
| `medium` | UTM medium or `organic` | 7 |
| `campaign` | UTM campaign or `evergreen` | 9 |
| `content` | CTA placement | 10 |
| `click_id` | Supplied id or per-session random id | 8 |

All values are restricted to ASCII letters, digits, and hyphens, so the complete payload stays within Telegram's 64-character start-parameter limit. Underscores are reserved as separators. No email, username, or other personal data is put in the payload.

## Bot-side requirement before calling this operational

The bot must parse and validate `ctx.startPayload` (or the framework's equivalent), preserve the first valid attribution on the Telegram user record, and log at least the Telegram user ID, video, language, source, medium, campaign, CTA content, click ID, timestamp, and subsequent funnel milestones. Repeated /start must not overwrite the original acquisition record without a deliberate last-touch policy.

Before release, inspect the live bot source and its persistent storage, then run a designated test through: tagged landing URL → each Telegram CTA → /start log → plan view → Stars invoice → successful payment → entitlement/access grant. Do not use a real payment or publish until the owner approves the test scope. A valid landing link alone does not prove bot-side attribution, payment, or access.

## Release gate

- Review English copy and page at `/en.html`.
- Confirm the current Pages deployment source/branch before merging; merging to `main` may publish the file automatically.
- Confirm the deployed route and links in a real browser.
- Verify bot parsing and logging before using this URL in a public video description.
- Only after those checks, add the tagged English landing URL to the YouTube description and verify the click path.
